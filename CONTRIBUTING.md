# Contributing

Issues and pull requests are welcome. This document says what a change has to
satisfy here, because most of it is unusual enough to be worth stating.

## Getting set up

```bash
npm install
npm test            # the deterministic suite, no network
npm run typecheck
npm run build
```

Two suites read the real site and are opt-in:

```bash
BIDE_LIVE=1 npm run test:live   # one request per route
BIDE_EVAL=1 npm run test:eval   # records nobody chose, held to their properties
```

Read `test/eval/README.md` before adding to either: the three tiers of test here
answer different questions, and mixing them is what makes a suite untrustworthy.

## The rule the whole project is built on

**This server never says anything the site did not.** Most of the code exists to
hold that line, and a pull request is read against it first:

- A failure is never an empty result. Six error codes, and a search the site
  refused is not a collection that holds nothing.
- A value the site did not print is `null`, never `0` and never a guess.
- A count is named after what it counts. Rows on a page are not a total, and a
  number this server computed is never presented as one the site published.
- A restriction that produced nothing says so rather than answering with an
  absence.
- Whatever the schema declares is enforced at runtime. Publishing
  `additionalProperties: false` and accepting an undeclared argument anyway is
  worse than declaring nothing.

## Tests come first

Fix a defect by writing the test that states the right answer, then change the
code. A test written afterwards only proves what the code already does.

Tests are deterministic or they do not exist. Anything touching time goes
through fake timers with a fixed epoch; there are no tolerance constants and no
real-clock measurements. The gate is **three consecutive identical runs**.

Markup is built, never captured: `test/builders` holds the shapes the site
publishes, and the fixtures under `test/fixtures` are generated by
`scripts/build-fixtures.mjs`. Nothing in this repository stores the text of a
third party.

## What we owe the site

Bide & Musique is run by a volunteer association, on one server, for free. A
change must not make this server ask for more:

- One request at a time, three seconds apart. The floor cannot be lowered by
  configuration, including through the published `./client` entry point.
- The User-Agent always carries the project and an address where someone can be
  reached, even when a caller supplies their own.
- A new route is weighed by what it costs. A page of a few tens of kilobytes is
  ordinary; one of several megabytes needs a reason.

## Writing

Every piece of text has to read on its own, to someone who has never seen a
previous version. No "as before", no "now", no "previously": describe what the
code does and **why**, never how it differs from a past state. The changelog is
the one place allowed to compare.

Comment the non-obvious — an invariant, an edge case, the reason behind a choice
that looks odd. A comment restating the name of the function it sits above is
noise.
